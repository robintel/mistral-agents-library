# ISA100 Wireless

**The industrial wireless standard for automation**: ISA100 Wireless is a
**standards-based wireless networking technology** developed by the **ISA100 Wireless
Compliance Institute (WCI)** for industrial automation applications. It is based on
the **IEC 62734** international standard and provides **interoperable, reliable, and
secure wireless communication** for industrial environments.

ISA100 Wireless builds upon **IEEE 802.15.4** and uses **IPv6** and **6LoWPAN** to
provide a **fully routable, IP-based wireless network** that enables seamless
integration with existing industrial networks and systems.

## Eras

The era is declared by the **ISA100 Wireless specification version** and **standardization timeline**.

**ISA100.11a-2009**: Initial release.
- **Standard**: First ISA100 Wireless standard
- **Based on**: IEEE 802.15.4-2006
- **Protocol**: ISA100.11a wireless protocol
- **Features**: Mesh networking, time synchronization, security
- **Status**: Foundation for subsequent versions
- **Standardization**: Basis for IEC 62734

**ISA100.11a-2011**: Enhanced capabilities.
- **Standard**: Updated ISA100 Wireless standard
- **Improvements**: Enhanced security, better network management
- **Features**: Improved routing, enhanced device support
- **Compatibility**: Backward compatible with 2009 version
- **Status**: Widely adopted

**IEC 62734 (2014)**: International standardization.
- **Standard**: International Electrotechnical Commission standard
- **Based on**: ISA100.11a-2011
- **Features**: Full ISA100 Wireless feature set
- **Adoption**: Global adoption and recognition
- **Status**: Current international standard

**ISA100.11a-2019**: Latest enhancements.
- **Standard**: Latest ISA100 Wireless standard
- **Improvements**: Enhanced security, better performance
- **Features**: Advanced network management, improved reliability
- **Use Cases**: Modern industrial wireless applications
- **Status**: Current, actively evolving

**ISA100 Wireless Compliance Institute (WCI)**:
- **Established**: 2009
- **Purpose**: Promote and ensure interoperability of ISA100 Wireless products
- **Certification**: WCI certification program for device compliance
- **Testing**: Interoperability testing and certification
- **Status**: Active organization supporting the standard

## Architecture

### Protocol Stack

ISA100 Wireless uses a **comprehensive protocol stack** based on open standards:

**Layer 7 - Application**: ISA100.11a Application Layer
- **Function**: Industrial application protocol and services
- **Services**: Process data access, device management, network management
- **Objects**: Application objects, data objects, management objects
- **Encoding**: Efficient binary encoding for industrial data

**Layer 6 - Presentation**: Data Representation
- **Function**: Data encoding and decoding
- **Encoding**: Common data representation formats
- **Compression**: Optional data compression
- **Security**: End-to-end security services

**Layer 5 - Session**: Transport Services
- **Function**: End-to-end communication services
- **Services**: Connection-oriented and connectionless services
- **Reliability**: Guaranteed delivery, flow control
- **Segmentation**: Message segmentation and reassembly

**Layer 4 - Transport**: IPv6 + UDP/ICMPv6
- **Function**: Network layer transport
- **Protocol**: IPv6 for addressing and routing
- **Transport**: UDP for most communications, ICMPv6 for network management
- **Addressing**: Full IPv6 addressing (128-bit addresses)
- **Multicast**: IPv6 multicast for one-to-many communication

**Layer 3 - Network**: 6LoWPAN + Mesh Routing
- **Function**: Network layer protocols and routing
- **6LoWPAN**: IPv6 over Low-power Wireless Personal Area Networks
  - Header compression for IPv6 packets
  - Fragmentation and reassembly for large packets
  - Neighbor discovery optimization
- **Mesh Routing**: Multi-hop routing through the network
  - Graph-based routing algorithms
  - Path selection based on metrics
  - Route repair and optimization
- **Address Resolution**: Mapping between short and long addresses

**Layer 2 - Data Link**: IEEE 802.15.4 + ISA100 Enhancements
- **Function**: Medium access control and frame formatting
- **Physical**: IEEE 802.15.4 compliant
- **MAC**: Enhanced CSMA/CA with TDMA for industrial use
- **Channel Access**: Time-slotted channel access (TSCA)
  - Time-division multiple access with channel hopping
  - Guaranteed time slots for critical traffic
  - Shared time slots for best-effort traffic
- **Frequency Hopping**: Channel hopping for interference avoidance
- **Blacklisting**: Avoid problematic channels
- **Beacon Management**: Network beacon transmission and management

**Layer 1 - Physical**: IEEE 802.15.4
- **Function**: Physical transmission and modulation
- **Frequency**: Multiple frequency bands
  - **2.4 GHz**: Global band (2.400-2.4835 GHz), 16 channels
  - **Sub-GHz**: Regional bands (varies by country)
    - 915 MHz (Americas)
    - 868 MHz (Europe)
    - Other regional bands
- **Modulation**:
  - **2.4 GHz**: O-QPSK (Offset Quadrature Phase Shift Keying)
  - **Sub-GHz**: Variants of O-QPSK or other modulations
- **Data Rate**: 250 kbps (2.4 GHz), lower rates for sub-GHz
- **Range**: 100-500 meters (depending on frequency and environment)
- **Power**: Maximum 20 dBm (100 mW) or as per regulations

### Network Topology

**Mesh Network**:
- **Self-Organizing**: Automatically forms and maintains mesh connections
- **Self-Healing**: Automatically reroutes around failures or obstructions
- **Multi-Hop**: Data can hop through multiple devices to reach destination
- **Redundancy**: Multiple paths between source and destination
- **Scalability**: Supports thousands of devices in a single network

**Device Roles**:

**Field Device**:
- **Function**: Sensor, actuator, or controller with ISA100 Wireless capability
- **Capabilities**:
  - Communicates with gateway, routers, and other field devices
  - Maintains mesh routing information
  - Participates in network management
  - Implements security services
- **Power**: Various power sources (line, battery, energy harvesting)
- **Classes**:
  - **Class 1**: Full function device (FFD)
  - **Class 2**: Reduced function device (RFD)

**Router**:
- **Function**: Dedicated routing device for network infrastructure
- **Capabilities**:
  - Full routing capabilities
  - Always powered (no battery operation)
  - Enhanced reliability and availability
  - Network management participation
- **Placement**: Strategic placement for optimal network coverage

**Gateway**:
- **Function**: Central access point to the wired network
- **Capabilities**:
  - Connects wireless network to host systems
  - Manages network configuration and security
  - Provides network clock synchronization
  - Handles data aggregation and protocol conversion
  - Implements security gateway functions
- **Interfaces**:
  - **Wired**: Ethernet, serial, or other wired connections
  - **Wireless**: ISA100 Wireless interface to the network

**Network Manager**:
- **Function**: Central management entity for the network
- **Capabilities**:
  - Network configuration and provisioning
  - Security management (key distribution, authentication)
  - Network monitoring and diagnostics
  - Route management and optimization
  - Time synchronization distribution
- **Implementation**: Can be integrated into gateway or separate device

**Security Manager**:
- **Function**: Central security management entity
- **Capabilities**:
  - Key generation and distribution
  - Authentication and authorization
  - Security policy enforcement
  - Security monitoring and audit
- **Implementation**: Typically integrated into gateway

### Network Formation and Operation

**Network Formation**:
1. **Discovery**: Network manager/gateway broadcasts network advertisement
2. **Join Request**: Device sends join request with credentials
3. **Authentication**: Network manager verifies device credentials
4. **Provisioning**: Network manager assigns address and configuration
5. **Neighbor Discovery**: Device discovers neighboring devices
6. **Route Discovery**: Device establishes routes to network manager and other devices
7. **Network Integration**: Device becomes operational in the network

**Time Synchronization**:
- **Network Time**: Global time synchronized across the network
- **Synchronization Source**: Network manager or gateway
- **Synchronization Method**: Beacon-based or message-based
- **Accuracy**: Microsecond-level synchronization
- **Drift Compensation**: Compensates for clock drift between devices

**Superframe Structure**:
- **Superframe**: Repeating pattern of time slots
- **Slot Duration**: Configurable (typically 10-100ms)
- **Time Slots**: Individual communication time slots
- **Dedicated Slots**: Slots assigned to specific links
- **Shared Slots**: Slots available for contention-based access
- **Channel Hopping**: Each slot uses a different channel
- **Blacklisting**: Skips channels with interference

**Frequency Hopping**:
- **Channel Set**: Set of channels used by the network
- **Hopping Sequence**: Pseudo-random sequence known to all devices
- **Dwell Time**: Time spent on each channel (one or more slots)
- **Channel Diversity**: Uses multiple channels for reliability
- **Regulatory Compliance**: Complies with regional regulations

## Common Defects and Mitigations

| Defect | Impact | Mitigation |
|--------|--------|------------|
| Device not joining | No connectivity | Verify join key, check network ID, test device configuration, verify authentication |
| Poor link quality | Data loss, latency | Check antenna, position, interference, adjust power, change channel |
| Network partition | Split network | Check routing, verify connectivity, test communication, check network manager |
| Gateway failure | Network outage | Verify gateway power, check connections, test gateway functionality, check redundancy |
| Authentication error | No access | Verify join key, check device credentials, test authentication, check security level |
| Encryption error | Security failure | Verify encryption keys, check key configuration, test encryption, check algorithm |
| Channel interference | Communication failure | Blacklist channel, change channel set, check interference sources, adjust frequency |
| Timeout error | Slow communication | Increase timeout, check network, verify device responsiveness, check routing |
| Route failure | Data loss | Check routing tables, verify network connectivity, test route discovery, check path metrics |
| IPv6 error | Addressing failure | Verify IPv6 configuration, check address assignment, test connectivity, check DNS |
| Battery failure | Device failure | Replace battery, check power source, monitor battery level, adjust power management |
| Memory error | Configuration loss | Reset device, reload configuration, check for memory corruption, verify firmware |
| Firmware error | Device malfunction | Update firmware, verify firmware version, check compatibility, test upgrade |
| Clock drift | Synchronization loss | Check clock synchronization, adjust drift compensation, verify time source |
| Network full | Cannot add devices | Increase network capacity, add routers, optimize network, check device limits |
| Key error | Security failure | Verify key configuration, rotate keys, check key distribution, test security |
| Blacklist error | Channel unavailable | Verify blacklist configuration, check interference, test channels, update blacklist |

```java
import java.io.IOException;
import org.apache.http.client.methods.HttpGet;
import org.apache.http.client.methods.HttpPost;
import org.apache.http.entity.StringEntity;
import org.apache.http.impl.client.CloseableHttpClient;
import org.apache.http.impl.client.HttpClients;
import org.apache.http.util.EntityUtils;
import org.json.JSONObject;

public class ISA100DeviceManager {
    
    private static final String GATEWAY_URL = "http://192.168.1.100:8080";
    private static final String USERNAME = "admin";
    private static final String PASSWORD = "password";
    
    private String token;
    private CloseableHttpClient httpClient;
    
    public ISA100DeviceManager() {
        this.httpClient = HttpClients.createDefault();
    }
    
    public void authenticate() throws IOException {
        String authUrl = GATEWAY_URL + "/api/v1/auth/login";
        HttpPost authPost = new HttpPost(authUrl);
        
        JSONObject authData = new JSONObject();
        authData.put("username", USERNAME);
        authData.put("password", PASSWORD);
        
        authPost.setHeader("Content-Type", "application/json");
        authPost.setEntity(new StringEntity(authData.toString()));
        
        String response = httpClient.execute(authPost, response -> {
            return EntityUtils.toString(response.getEntity());
        });
        
        JSONObject jsonResponse = new JSONObject(response);
        this.token = jsonResponse.getString("token");
        System.out.println("Authenticated successfully");
    }
    
    public JSONObject getNetworkConfig() throws IOException {
        String url = GATEWAY_URL + "/api/v1/network/config";
        HttpGet request = new HttpGet(url);
        request.setHeader("Authorization", "Bearer " + token);
        
        String response = httpClient.execute(request, response -> {
            return EntityUtils.toString(response.getEntity());
        });
        
        return new JSONObject(response);
    }
    
    public JSONObject getDeviceList() throws IOException {
        String url = GATEWAY_URL + "/api/v1/devices";
        HttpGet request = new HttpGet(url);
        request.setHeader("Authorization", "Bearer " + token);
        
        String response = httpClient.execute(request, response -> {
            return EntityUtils.toString(response.getEntity());
        });
        
        return new JSONObject(response);
    }
    
    public void addDevice(String nickname, String eui64, String deviceType) throws IOException {
        String url = GATEWAY_URL + "/api/v1/devices";
        HttpPost request = new HttpPost(url);
        request.setHeader("Authorization", "Bearer " + token);
        request.setHeader("Content-Type", "application/json");
        
        JSONObject deviceData = new JSONObject();
        deviceData.put("nickname", nickname);
        deviceData.put("eui64", eui64);
        deviceData.put("type", deviceType);
        
        request.setEntity(new StringEntity(deviceData.toString()));
        
        String response = httpClient.execute(request, response -> {
            return EntityUtils.toString(response.getEntity());
        });
        
        System.out.println("Device added: " + response);
    }
    
    public static void main(String[] args) {
        try {
            ISA100DeviceManager manager = new ISA100DeviceManager();
            manager.authenticate();
            
            // Get network configuration
            JSONObject config = manager.getNetworkConfig();
            System.out.println("Network Config: " + config.toString(2));
            
            // Get device list
            JSONObject devices = manager.getDeviceList();
            System.out.println("Devices: " + devices.toString(2));
            
        } catch (IOException e) {
            e.printStackTrace();
        }
    }
}
```

### C (ISA100 Wireless Embedded Device)
```c
#include <stdio.h>
#include <string.h>
#include <stdlib.h>
#include "isa100.h"  // ISA100 Wireless stack header

// Device configuration
#define DEVICE_NICKNAME "TemperatureSensor"
#define DEVICE_TYPE "FieldDevice"
#define JOIN_PRIORITY 1

// Security configuration
uint8_t joinKey[16] = {0x00, 0x01, 0x02, 0x03, 0x04, 0x05, 0x06, 0x07,
                      0x08, 0x09, 0x0A, 0x0B, 0x0C, 0x0D, 0x0E, 0x0F};

// Callback functions
void onNetworkJoinSuccess(uint8_t networkId, uint16_t shortAddress) {
    printf("Joined network %d with address %d\n", networkId, shortAddress);
}

void onNetworkJoinFailure(uint8_t reason) {
    printf("Join failed with reason: %d\n", reason);
}

void onMessageReceived(uint8_t *data, uint16_t length, uint16_t sourceAddress) {
    printf("Received %d bytes from address %d\n", length, sourceAddress);
    // Process received message
}

void onTimeSync(uint32_t asn, uint32_t utcTime) {
    printf("Time sync: ASN=%lu, UTC=%lu\n", asn, utcTime);
}

int main() {
    ISA100_Status status;
    
    // Initialize ISA100 Wireless stack
    status = ISA100_Initialize();
    if (status != ISA100_STATUS_OK) {
        printf("ISA100 Initialize failed: %d\n", status);
        return 1;
    }
    
    // Configure device
    ISA100_DeviceConfig config;
    memset(&config, 0, sizeof(config));
    strcpy(config.nickname, DEVICE_NICKNAME);
    strcpy(config.deviceType, DEVICE_TYPE);
    config.joinPriority = JOIN_PRIORITY;
    memcpy(config.joinKey, joinKey, 16);
    
    // Set callbacks
    ISA100_SetJoinSuccessCallback(onNetworkJoinSuccess);
    ISA100_SetJoinFailureCallback(onNetworkJoinFailure);
    ISA100_SetMessageReceivedCallback(onMessageReceived);
    ISA100_SetTimeSyncCallback(onTimeSync);
    
    // Configure device
    status = ISA100_ConfigureDevice(&config);
    if (status != ISA100_STATUS_OK) {
        printf("ISA100 Configure failed: %d\n", status);
        return 1;
    }
    
    // Start device
    status = ISA100_Start();
    if (status != ISA100_STATUS_OK) {
        printf("ISA100 Start failed: %d\n", status);
        return 1;
    }
    
    printf("ISA100 Wireless device started\n");
    
    // Main loop
    while (1) {
        // Process ISA100 events
        ISA100_ProcessEvents();
        
        // Application logic here
        
        // Sleep for a while
        #ifdef _WIN32
        Sleep(100);
        #else
        usleep(100000);  // 100ms
        #endif
    }
    
    // Cleanup (never reached in this example)
    ISA100_Stop();
    ISA100_Cleanup();
    
    return 0;
}
```

## Standing Rules

1. **IPv6 First**: ISA100 Wireless is fundamentally an IPv6 network. Always design
   with IPv6 addressing and routing in mind, even when integrating with IPv4 systems.
2. **Security by Default**: Security is mandatory, not optional. Always enable
   appropriate security levels, use strong encryption, and implement proper
   authentication and authorization.
3. **Interoperability**: ISA100 Wireless is designed for interoperability. Choose
   standard-compliant devices, follow standard practices, and test interoperability.
4. **Reliability Through Diversity**: Achieve reliability through channel diversity,
   path diversity, and temporal diversity (frequency hopping, time slotting).
5. **Network Management**: Proper network management is essential. Implement
   centralized management for configuration, security, monitoring, and diagnostics.
6. **Power Awareness**: Be aware of power constraints. Optimize communication
   patterns, use appropriate power modes, and consider energy efficiency.
7. **Regulatory Compliance**: Always ensure compliance with local regulations
   for frequency usage, power levels, and other radio requirements.
8. **Testing**: Thoroughly test network operation, device interoperability, and
   application functionality before deployment.
9. **Documentation**: Document network design, device configurations, security
   settings, and operational procedures for maintenance and troubleshooting.
10. **Continuous Improvement**: Regularly assess network performance, review
    security settings, and update configurations to maintain optimal operation.
