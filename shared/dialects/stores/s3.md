# Amazon S3

The de-facto standard for object storage. Every byte is an object; every
object has a key. The contract covers the behavior that matters to code
that stores, retrieves, or processes S3 objects — not the AWS console.

## Core discipline

1. **Keys are paths, but not paths** — forward slashes are allowed and
   common, but the store is flat; a key named `a/b/c` is a single
   object, not three. List operations simulate directories by prefix.
2. **Eventual consistency is the default** — reads after writes may not
   see the write immediately. Strong consistency is available but must
   be explicitly requested (and paid for).
3. **No partial updates** — an object is replaced entirely; there is no
   in-place modification. Concurrent writers to the same key win by
   last-writer-wins unless you provide your own locking.
4. **Metadata is part of the object** — system metadata (content-type,
   content-length, etc.) and user metadata (arbitrary key-value pairs)
   travel with the object. Metadata updates are separate operations.
5. **Immutability by convention** — S3 itself allows overwrites, but
   the immutability pattern is: new key per version, or enable
   object versioning and treat the version ID as the key.

## Era map

- **2006-2023**: The basics — buckets, keys, GET/PUT/DELETE/HEAD/LIST
- **2023+**: Strong consistency for most operations, dual-layer
  encryption (SSE-S3 + SSE-KMS), and event notifications as the
  canonical CDC trigger

## Access patterns that matter

| Pattern | When | Watch out for |
|---------|------|---------------|
| write-once, read-many | static assets, backups | cache invalidation |
| write-once, process-once | ETL input/output | idempotent processing |
| append-only log | event sourcing | no S3-native append; use multi-part upload or separate keys |
| versioned artifacts | deployables, configs | list performance; use prefix + delimiter |
| lifecycle tiers | hot/warm/cold/glacier | transition lag, restore time |

## Integrations

- **CDC**: S3 Event Notifications → SQS/SNS/Lambda for near-real-time
- **ETL**: S3 as source/sink for Spark/Glue/Athena; partition by prefix
- **Backup**: Cross-region replication for DR, versioning for point-in-time
- **Security**: SSE-S3, SSE-KMS, bucket policies, IAM conditions, VPC
  endpoints

## Cost levers

- Storage class by age (Standard → IA → Glacier → Glacier Deep Archive)
- Request pricing: GET is cheap, LIST is expensive; minimize LIST via
  prefix design
- Transfer out is charged; prefer same-region consumers

## Defects that bite

- Eventual consistency on LIST after DELETE: a deleted object may
  still appear briefly
- Multi-part uploads left incomplete consume storage; enforce abort
  policy
- Bucket name is global; choose carefully
- 5 GB limit per PUT; use multi-part upload above that
